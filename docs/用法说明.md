# Ollama 模型切换器 · 使用说明（轻量通道 + 快翻 / 精翻 + 语音转文字）

双击 `Ollama-Model-Switcher.exe` 即可运行，单文件、无需安装 .NET 之外的任何东西（系统自带 .NET Framework 4.8）。

> 界面 2026-11-18 全面改版：正文与按钮字号统一放大（正文 9.8pt、标题 11pt、数据 15pt），按钮统一为圆角三色样式（主操作蓝、次操作灰、危险红），卡片内长句说明改为「鼠标悬停标题」查看，列表表头统一深色。

主界面现在有三个模型角色：**主力**（精翻用，默认 `qwen3.5-9b-local:latest`）、**批量**（备用，默认 `translategemma:4b`）、**轻量**（快翻用，默认 `qwen3.5-0.8b-local:latest`，约占 0.7 GB 显存）。三者都可以在下拉框里换成本机已下载的其他模型。顶栏还多了「语音转文字」入口。

---

## 一、轻量通道（新增）

「游戏模式」下面新加了一行「轻量通道」：

- 下拉选择轻量模型（默认 `qwen3.5-0.8b-local:latest`）。
- 「加载到显存」：先卸载其他驻留模型，再加载轻量模型，避免 8 GB 显存被挤爆；右侧文字会显示「已驻留 0.73 GB · 快翻可用」。
- 「卸载」：立即把它从显存里释放。
- 不手动加载也没关系，翻译窗口选「快翻」时会自动加载。

## 二、模型调用接口（给浏览器翻译插件 / 其他工具用）

主界面下方新增「模型调用接口」区块：

| 项目 | 值 |
| --- | --- |
| OpenAI 兼容地址 | `http://127.0.0.1:11434/v1` |
| Ollama 原生地址 | `http://127.0.0.1:11434/api` |
| 模型名 | 下拉里选，默认是「主力模型」，右侧徽标会提示这是主力 / 批量 / 轻量模型 |

每个地址右边都有「复制」按钮，点一下直接进剪贴板，下方会提示「已复制：…」。

### 插件里怎么填

以浏览器翻译插件为例：

- **base URL / 接口地址**：填 `http://127.0.0.1:11434/v1`（OpenAI 兼容最通用）
- **model / 模型名**：填下拉里显示的那串，例如 `qwen3.5-9b-local:latest`
- **API Key**：随便填（如 `ollama`）或留空都行，本地服务不校验

### 报错时先看这几条

1. 主界面左上角的绿点是否亮着、「已连接」是否显示 —— 不亮就先点「启动服务」。
2. 模型是否已经出现在「驻留显存」里 —— 没驻留也能用（首次请求会自动加载），但会等几十秒。
3. 地址是否填成了 `localhost` 以外的别名，建议直接用 `127.0.0.1`。

## 三、一键翻译

点主界面右上角的「一键翻译」按钮（蓝色），打开翻译窗口。

### 快翻 / 精翻（新增）

窗口右上角可以切换翻译模式：

| 模式 | 用的模型 | 实测速度 | 适合 |
| --- | --- | --- | --- |
| 快翻 | 轻量模型（默认 `qwen3.5-0.8b-local:latest`） | 热态 54–56 字/秒，一段合规通知约 2 秒 | 先看懂大意、批量粗翻、显存紧张 |
| 精翻 | 主力模型（默认 `qwen3.5-9b-local:latest`） | 热态 7–11 字/秒，同一段约 3 分钟（含冷加载） | 对外交付、术语和语气要求高 |

默认是**精翻**。开始前会先估显存：预计明显放不下就直接改用快翻，状态栏会写「显存不足（需 x GB，可用 y GB），已自动降级为快翻」；如果模型加载后大部分层被挤到内存，也会自动降级并提示。快翻会明显更快，质量略低于精翻，正式文档建议先用快翻试读、再用精翻出终稿。

### 支持的格式

| 格式 | 处理方式 | 输出 |
| --- | --- | --- |
| `.docx` | 复制原件后只替换文字，保留原段落结构、样式、表格 | `<原名>_译文.docx` |
| `.pdf` | 逐页渲染 → OCR 识别（自动判别文字体系） → 分段翻译 | `<原名>_译文.docx`，按「第 N 页」分段，每段译文后跟灰色小字原文，便于对照 |
| `.png` / `.jpg` / `.jpeg` | 按「识别语言」OCR → 翻译 | 界面左右栏显示识别原文与译文，同时另存 `<原名>_译文.docx` |

标题栏的**识别语言**可选「自动识别 / 中文 / 英文 / 俄文·西里尔」，默认自动：先判断页面是汉字还是西里尔字母，再选对应引擎。俄语、乌兹别克语等西里尔文用内置引擎，不依赖系统语言包（首次使用会解压约 45MB 到临时目录，之后复用）。

**原件绝不会被覆盖**：所有结果都写到输出目录里的新文件。输出目录默认是
**exe 同级的 `翻译结果\年月日_时分秒\`**（若该位置被安全软件拦住，会自动退到 `C:\Users\<你>\Ollama翻译\…`），窗口底部实时显示，点「打开输出目录」直接跳转。

### 操作步骤

1. 把文件拖到虚线框里（或点虚线框 / 「选择文件…」），可一次多个。
2. 点「开始翻译」。
3. 列表里的「状态」列会显示进度，例如：
   - `识别文字 第 1/3 页`
   - `共 42 段，分 8 批翻译`
   - `翻译第 3/8 批（共 42 段）`
   - `逐段翻译 第 12/42 段`（分隔符没被模型保住时自动逐段兜底）
4. 某个文件失败只会在它自己那行显示「失败：原因」，其余文件继续处理。
5. 需要中断时点「停止」——等当前这一段返回后停下，已翻部分会保存（见下节）。

### 分段翻译与中断保留（新增）

长文档是按小段分批处理的：`.docx` 每批最多 6 段 / 1100 字，PDF 按页处理。**每翻完一批（PDF 每翻完一页），就立刻把已翻内容写进输出文件**：

- `.docx`：已翻的段落替换成译文，还没翻到的段落先保留原文，文件随时能打开；
- `.pdf` / 图片：已完成的页先写进 `<原名>_译文.docx`，PDF 中断后文件末尾会有一行「（未完成：已翻 N 页，共 M 页）」，一眼能看出翻到哪。

中途点「停止」时，列表状态会变成「已停止 · 已翻部分已保存」并给出文件链接——**之前翻好的内容不会丢**。一个文件都还没翻完就停止时显示「已停止 · 尚未产生译文」。

这样大文件可以先翻一部分看效果，不满意再换模型；关掉窗口或换机器前，已产出的译文都是完整的 docx 文件。

### 用的模型

- 快翻：配置里的**轻量模型**（默认 `qwen3.5-0.8b-local:latest`）
- 精翻：配置里的**主力模型**（默认 `qwen3.5-9b-local:latest`）

翻译时会自动关闭「思考模式」（`think:false`），否则这类思考型模型的正文经常为空、长请求还会卡住。开始前会先卸载其他驻留模型，把显存让给当前要用的模型，并保持 30 分钟（`keep_alive`）。

### 速度说明

只跑本地显卡，速度取决于本机状态。实测：0.8B 快翻热态约 54–56 字/秒，9B 精翻约 7–11 字/秒；一页 A4 文字精翻通常要十几秒到一分钟，长文档会更久。长文档请耐心看进度，界面不会卡死（翻译在后台线程跑）。

### 已知边界

- 只认 `.docx`（老式 `.doc` 请先在 Word 里另存为 docx）。
- PDF 走「渲染成图 + OCR」，扫描件也能处理，但会有识别误差；排版不逐字还原，按页/段对照。
- 中文、英文 OCR 用系统语言包；俄文/乌兹别克语等西里尔文用内置引擎，不需要额外装语言包。目录页的点线可能被识别成杂字，程序会尽量清理，但不保证干净。
- 原文本身就是中文时会翻译成英文（便于反向使用）。

## 四、语音转文字（新增）

点主界面顶栏的「语音转文字」，打开转写窗口。

### 它怎么工作

1. **Whisper small** 先把音频识别成文字（CPU 跑，不占显存）；
2. **轻量模型（0.8B）** 只做错别字和标点校对，不做文风改写。

识别和润色都在本机完成，音频不会上传。左侧是 Whisper 原文，右侧是润色文本，右侧可以直接手动修改后再复制或另存。

### 支持的格式

`wav / mp3 / m4a / aac / flac / ogg / opus / wma / mp4 / mkv / mov / webm` —— 只要有音轨，视频文件也能直接转。

### 操作步骤

1. 把音频拖到虚线框（或点「选择文件…」），可一次多个；
2. 右上角选音频语言：中文 / 英文 / 自动识别；
3. 点「开始转写」；
4. 列表里会实时显示识别进度（如 `识别中 01:23 / 05:40…`）；
5. 结果输出到 exe 同级的 `转写结果\年月日_时分秒\`：
   - `<原名>_转写.docx`：含「识别原文」和「润色后文本」两段；
   - `<原名>_转写.txt`：润色后的纯文本（润色失败时保存原文）。

### 实测速度

i9-13900H（CPU、small 模型、int8、8 线程）：14.8 秒中文音频，模型加载 1.8 秒 + 转写 4.8 秒，约 3 倍实时；1 小时录音大约 20 分钟。转写期间不占显存，润色时才加载 0.8B（约 0.7 GB）。

### 运行前提

语音引擎（Python 运行时 + faster-whisper + Whisper small 模型）已经全部打包进 exe，**不需要另外装 Python**：

- 第一次点「开始转写」时，程序会把内置引擎和模型释放到 `%TEMP%\OllamaModelSwitcher\asr-cache`（约 600 MB，通常几秒）；
- 释放一次后长期复用，后续启动不再重复解压；
- 如果本机已经有 faster-whisper 模型目录，可在「设置 → 语音转文字」里指定，程序会直接使用，跳过模型解压；
- 想换模型时，把 `AsrModel` 指向新的 faster-whisper 模型目录即可（需含 `model.bin` / `config.json` / `tokenizer.json` / `vocabulary.txt`）。

### 已知边界

- CPU 转写，长录音耗时约为音频时长的 1/3；
- 识别质量取决于录音清晰度，同音字（如「纪要 / 计要」）可能识别错，右侧可直接改；
- 0.8B 润色只保证标点和明显错字，不保证术语完全正确，正式文稿建议人工过一遍。
